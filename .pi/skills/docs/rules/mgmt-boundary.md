# docs is truth, .heio is day to day

`docs/` is committed. A clone sees it. Write here when the next person needs the note without this machine.

`.heio/` is local working memory. Git ignores it. Issues, plans, tasks, the journal, and working reports live there.

Do not keep two living copies. Promote a finished plan by writing the durable outcome as an ADR, spec, architecture note, or guide. Then close the working file with the **management** skill.

Do not copy a plan into `docs/` as a plan. The kind must change.

This skill stops at `docs/`.
