# Ship a real program

## Description

Pick a small real target (CLI tool, game loop, WASM demo, etc.) and drive language/toolchain gaps from actual use instead of checklist expansion alone.

## Affected

- New `examples/` or `apps/` tree
- Gaps filed back to Roadmap or vault issues
- JS and/or native build paths

## Observed

Conformance fixtures do not stress packaging, DX, or “would a human keep using this?”.

## Impact

Unknown product fit; wrong Phase 2 priorities.

## Proposed Fix

1. Choose one target (goal, js vs native, success demo) and write it down.
2. Program in-repo; builds via `draconic`.
3. Gap list as Roadmap todos or issues as they appear.
4. Demo path: clone → build → run → observe.
5. Short write-up: solid vs blocked.

## Locked decisions (human)

1. **Target:** small portable FizzBuzz CLI-style Program under `examples/fizzbuzz/`
2. **Backend:** portable — must build/run on **js**; native if trivial, not required
3. **Success demo:** `cargo run -p draconic-cli -- build --target js examples/fizzbuzz/main.drac -o /tmp/fizzbuzz.js` → `node /tmp/fizzbuzz.js` prints 1..20 FizzBuzz
4. **Home:** `examples/`
5. **Gaps:** note in example NOTES/README; Roadmap todos only for crisp real gaps

## Shipped

- `examples/fizzbuzz/main.drac` — FizzBuzz 1..20 via `globalThis.console.log`
- `examples/fizzbuzz/README.md` — demo path + expected output
- `examples/README.md` — index (fizzbuzz + existing todo)

### Demo (verified)

```bash
cargo run -p draconic-cli -- build --target js examples/fizzbuzz/main.drac -o /tmp/fizzbuzz.js
node /tmp/fizzbuzz.js
```

Prints classic FizzBuzz lines for 1..20.

### Solid vs blocked

| Area | Status |
|------|--------|
| Control flow (`for`, `if`/`else`, `%`) | Solid |
| Strings + `String(n)` | Solid |
| JS build + Node run | Solid |
| Host console I/O | Solid via `globalThis.console` (free `console` unresolved) |
| Native backend for this Program | Not required; console/globalThis is JS-host pattern |
