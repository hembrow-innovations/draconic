# Complete Roadmap seed data

## Description

Finish the Roadmap **seed data** so platform capability tracks are fully seeded the way **H** and **K** already are: Loop-sized `todo` rows, concrete **Tests** paths, parent/child structure where clusters are too large for one Loop, and critical-path notes where a success demo depends on order.

**H** (ADR-0008 / [[issues-16-roadmap-e2e-http-server]]) and **K** (ADR-0009 / [[issues-17-roadmap-git-package-manager]]) were seeded with deep children + v1 done bars. **F / C / L / D / R** (and light **P / S** extras) still look like first-pass parent seeds — often one row per cluster, uneven child depth, no critical-path / v1-done notes. Completing seed data means closing that gap **without inventing new product directions**.

## Affected

- `ROADMAP.md` — sections **F**, **C**, **L**, **D**, **R**; review **P** / **S** / residual **N** / **U** for incomplete seeds only
- Legend / “How the Loop updates” if seed policy needs one line of clarity
- Optional ADRs only if a seed pass surfaces a locked decision that is not already ADR-0008/0009

## Impact

- Loop claims coarse parents and either under-delivers or balloons one session.
- Critical-path work (e.g. FFI → real systems demos, install path for distribution) has no ordered bar like H→http-echo or K→temp-git e2e.
- Half-seeded tracks invite ad-hoc invention when the board looks “thin” on a track despite parent rows existing.

## Proposed Fix

1. **Audit** F/C/L/D/R (and P/S/N residual) against H/K quality bar:
   - Each row = one Loop (or split to `X.NN` children).
   - **Targets** + **Tests** path real or clearly “create on implement”.
   - No silent feature invention beyond capability already named in the parent row / legend.
2. **Expand** only where a parent is larger than one Loop (e.g. F07 bindgen, C01 workers, L05 test framework, D01 install matrix, R02 permissions) into atomic children.
3. **Add** short critical-path / v1-done notes per track where a demo or bar is already implied (do not invent new flagship demos without human gate).
4. **Do not** mark any new seed `done`; implementation stays **draconic-loop**.
5. **Do not** delete historical B/E/T/N/U rows.
