# Collapse LLVM multi-path façade into one lowerer

Parent: [[issues-6-architecture-cleanup]]

## Blocked by

Prefer [[issues-9-runtime-abi-seam]] first (shared declare/print helpers); not a hard code block if ABI work is folded into this change.

## Description

`emit_llvm_ir` routes native / Promise / eval predicates else **hello stub success**. Three deep slices re-walk IR; unsupported Programs silently “work.”

## Affected

LLVM backend public emit + native binary build; conformance fixtures on native target that currently pass via stub.

## Observed

Classify often runs twice (is_ then emit_). Tests assert stub absence when a real path should win. ADR-0002 (shared IR, dual backends) remains; this is LLVM honesty, not an AST fork.

## Impact

False native greens; hard to grow a general LLVM path.

## Proposed Fix

One lowerer with internal adapters; hard-error unsupported; retarget stub-only fixtures.

## Agent Brief

### Goal

Replace the LLVM backend’s multi-predicate façade and hello-stub success path with one coherent lowerer interface and honest failure for unsupported IR.

### Contract

- Public backend interface stays small (`emit_llvm_ir` / `build_native_binary` or equivalent). Internals may keep native / Promise / eval as **private** adapters.
- Unsupported IR for the native target yields a **Diagnostic** (or equivalent hard error) — not a successful hello binary.
- Programs that today correctly take native-int, Promise/async, or eval paths keep equivalent observable behavior.
- Conformance: fixtures that only passed on native because of the hello stub must be retargeted to js-only (or given real native coverage). No silent stub greens.
- ADR-0002 stands: one shared IR, two backends. Do not fork from typed AST per backend.
- Prefer shared LLVM-text helpers and Runtime ABI surface ([[issues-9-runtime-abi-seam]]) rather than triplicating declares.

### Acceptance criteria

1. No successful native emit path that only links/runs the Runtime hello stub for arbitrary unsupported Programs.
2. Unsupported native Programs surface a clear diagnostic.
3. Existing real native paths (native types, Promise/async subset, eval fold subset) still pass their tests/fixtures.
4. Conformance native results do not count stub-hello as feature coverage; fixture metadata adjusted where needed.
5. `cargo test --workspace` green.

### Out of scope

- Full general ES→LLVM lowering of the entire language surface.
- Changing JS backend behavior.
- Deepening async into IR nodes ([[issues-15-deepen-ir-backend-diverge]]).
- Unifying Embed fold ([[issues-14-unify-eval-embed-fold]]) beyond what’s needed to keep eval path working.

## Resolution

Closed 2026-07-26.

- `emit_llvm_ir` is one lowerer: private adapters (native ints/layouts, Promise/async, eval/Function); empty program → B08 Runtime hello; all other IR → hard `Diagnostic`.
- Removed hello-stub success for arbitrary unsupported Programs.
- Retargeted 149 stub-only native fixtures to `js` (kept `smoke/empty` + real native paths: native/*, es/async/*, es/eval/*).
- Conformance harness no longer defaults `native.stdout` to `hello\n`.
- CLI/integration native e2e uses real `i32` program; new tests assert unsupported JS fails native emit.
