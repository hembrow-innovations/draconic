# Unify eval folding with Embed interpreter

Parent: [[issues-6-architecture-cleanup]]

## Blocked by

Prefer stable N07 surface; optional after [[issues-10-collapse-llvm-multipath]] if touching es_eval layout.

## Description

N07 uses two IR interpreters (backend Folder + Embed) and value adapters. Deepen Embed; thin observation emit on LLVM path.

## Affected

Embed public eval interface; LLVM eval emit path; eval conformance fixtures.

## Observed

Outer fold in backend; string eval in Embed; bidirectional value map; print constants only on native.

## Impact

Eval bugs hide in adapters; Embed tests miss program-level fold.

## Proposed Fix

One value domain in Embed; es_eval prints observations only.

## Agent Brief

### Goal

Unify **Embed** and the LLVM eval fold path so eval semantics live in one interpreter / one value domain; LLVM only emits observations for the native binary.

### Contract

- Embed remains the place that compiles-and-evaluates source strings for `eval` / `Function` (and may own outer Program fold).
- No long-term dual value types requiring bidirectional adapters between backend Folder and Embed.
- N07 conformance fixtures keep the same observable native stdout / success criteria.
- Domain: Embed, Runtime (eval is still fold-at-emit unless this issue explicitly introduces runtime compile — default: **keep fold-at-emit**).

### Acceptance criteria

1. Single interpreter owns fold/eval value semantics used by N07.
2. Bidirectional Folder↔Embed value adapters are gone (or reduced to a trivial newtype with no semantic mapping).
3. Eval-related unit tests and conformance fixtures green on applicable targets.
4. `cargo test --workspace` green.

### Out of scope

- Shipping a full runtime JIT or interpreting the entire language on native.
- Changing direct vs indirect eval lexical rules (preserve current observations).
- General LLVM multi-path collapse except as needed to keep the eval adapter thin ([[issues-10-collapse-llvm-multipath]]).

## Resolution

Closed 2026-07-26.

- Outer Program fold lives in Embed (`fold_eval_program` / `Observation`); primitives are `EmbedValue` via `Value::Prim`.
- Backend `es_eval` is observation-only: classify tag + emit print LLVM; no Folder, no `value_to_embed` / `embed_to_value`.
- N07.02–N07.04 unit tests + conformance fixtures unchanged and green; `cargo test --workspace` green.
