# Public Learn and Reference versus this vault

## Overview

Public language docs are a static site generated by a Draconic Program, not this vault and not mdBook, Starlight, or VitePress. Sources live in `website/` as a markdown subset. The generator emits HTML with two sections, **Learn** and **Reference**. GitHub Pages is the public host. Agent and Toolchain notes stay under `docs/` ([[0010-public-docs-draconic-ssg]]). Orientation: [[overview-toolchain]], [[overview-vault]].

## Prerequisites

- **Read `website/` as source**: `.md` files with `title`, `section`, and `status` frontmatter. Do not treat generated `.html` as the source of truth.
- **Native LLVM**: `scripts/generate-website.sh` builds `website/generate.drac` with `--target native`.
- **Know the split**: this vault ([[standards-docs-vault]]) is for agents and maintainers. Learn and Reference are for people writing Programs.

## Steps

1. **Edit markdown in `website/`**, not vault notes, when the change is public language teaching or working reference.

2. **Stay inside the subset**: headings, paragraphs, lists, code fences, links, and status frontmatter. That is what `website/generate.drac` renders.

3. **Tag each page `shipped` or `not-yet`**. Copy-paste code exists only on shipped pages and must build. CI extracts those fences and compiles them. Playground and in-page runners are later ([[0010-public-docs-draconic-ssg]]).

4. **Generate locally** with `scripts/generate-website.sh`. It compiles the generator, runs it, and stages HTML under `dist/pages` (Learn is also copied to `index.html`).

5. **Publish path**: GitHub Pages publishes the generated HTML from CI ([[0010-public-docs-draconic-ssg]]). Dist is not committed as source.

6. **Keep agent docs in `docs/`**. CLI internals, Loop, NFRs, and Embed APIs belong here ([[api-cli]], [[api-embed]], [[guides-loop]], [[guides-toolchain]]). Do not serve the vault as the site.

## Examples

Learn path (from `website/learn.md`): Install, then from JavaScript or from systems, joining at Dual worlds, then modules, native types, host I/O, packages.

Reference path (from `website/reference.md`): CLI, types, Dual-world rules, host I/O, packages. Working pages while writing a Program, not a generated API dump. The vault API notes ([[api-cli]], [[api-embed]]) are the command and crate contracts for agents.

Status in `website/*.md` as of this note:

- **shipped**: Learn, Reference, Install, from JavaScript, CLI
- **not-yet**: from systems, Dual worlds, modules, native types, host I/O, packages, types, Dual-world rules, Reference host I/O, Reference packages

Shipped pages may include copy-paste fences. Not-yet pages stay prose.

Incorrect:

- **Vault as site**: publishing `docs/` to GitHub Pages
- **Node docs generator as truth**: VitePress or similar replacing `website/generate.drac`
- **Copy-paste on not-yet**: a fence on a `status: not-yet` page
- **Documenting samples that do not compile** on shipped pages
