# Triage

Move ticket notes under `.heio/planning/tickets/` through **management** status.

Load **management**. That skill owns paths, templates, ids, status, and close-moves. Load **docs** for committed truth and for durable rejection notes. Load **to-slices** and **to-tasks** when promoting.

Any triage notes or comment block you add to a ticket must start with:

```
> *This was generated by AI during triage.*
```

## Creating a note

Copy the management ticket template. **management** owns `<NN>`. Scan live folders and `.heio/archive`. Never pick the id by eye from the live folder alone.

## Reference docs

- [AGENT-BRIEF.md](AGENT-BRIEF.md). How to write durable agent briefs on tasks.
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md). How rejected-feature notes work under **docs**.

## Status

Ticket `status` is `open` / `parked` / `promoted` / `dropped` / `closed`. Nothing else.

Optional triage tags (not status): `needs-triage`, `needs-info`. Category rides on `tags` and `labels` (`bug` or `enhancement`) plus optional `ticket_type`.

- `open` — inbound or still being triaged
- `parked` — belongs to the project, not an active slice
- `promoted` — fanned into a slice and tasks. The task is the executable
- `dropped` — will not be actioned
- `closed` — done

A task is the AFK unit (`status: ready`). Do not execute from a ticket.

### Terminal states are a flip and a move

Live folders hold only live tickets. The moment a ticket reaches `closed` or `dropped`, set the status and **obsidian-axi** `mv` it to `.heio/archive/planning/tickets/`. Keep the filename. **management** owns the move.

## Invocation

The maintainer describes what they want. Interpret the request and act. Refer to tickets by note slug or `ticket-<NN>`.

- "Show me anything that needs my attention"
- "Let's look at ticket-42-foo"
- "Promote ticket-42-foo"
- "What's parked?"

## Show what needs attention

Scan `.heio/planning/tickets/`. Read each note's frontmatter and present three buckets, oldest first (by `created_at`):

1. **Untriaged.** `status: open` with no state tag.
2. **`needs-triage`.** Evaluation in progress.
3. **`needs-info`** with reporter activity in `## Comments` since the last triage notes.

Show counts and a one-line summary per ticket. Let the maintainer pick.

## Triage a specific ticket

1. **Gather context.** Read the full ticket note. Explore the codebase using the project's domain glossary discovered under `docs/`. Run two checks:
   - **redundancy.** Search for an existing implementation. If found, recommend `dropped` (already implemented).
   - **prior rejection.** Search `docs/` for rejection notes (see [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)).

2. **Recommend.** Tell the maintainer your `ticket_type` and status recommendation. Wait for direction.

3. **Verify the claim.** For a bug, reproduce it. Report confirmed, failed, or insufficient detail (`needs-info`).

4. **Plan (if needed).** If the ticket needs fleshing out, run a **design-tree** session.

5. **Apply the outcome.** Set `status` / `tags`, then write to the note:
   - `promoted`. Load **to-slices** and **to-tasks**. Put the agent brief on the task, not the ticket.
   - `parked`. Fits the project, later slice.
   - `needs-info`. Append triage notes under `## Comments`. Leave `status: open`.
   - `dropped` (already implemented). Point at where it lives. Move to archive.
   - `dropped` (enhancement). Write a durable rejection note through **docs**, then move to archive ([OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)).
   - `closed`. Work landed. Move to archive.
   - `open` + `needs-triage`. Optional `## Comments` if there's partial progress.

## Quick state override

If the maintainer names a management status, trust them and set frontmatter directly. Confirm what you're about to do, then act.

## Needs-info template

Append under the note's `## Comments` heading:

```markdown
> *This was generated by AI during triage.*

## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you:**

- question 1
- question 2
```

## Resuming a previous session

If prior triage notes exist in the note's `## Comments`, read them, check whether the reporter has answered any outstanding questions, and present an updated picture before continuing. Don't re-ask resolved questions.
