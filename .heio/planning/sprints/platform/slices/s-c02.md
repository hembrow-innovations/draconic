# C02 Message-passing channels: send/recv; structured-clone or transfer policy; bounded buffer as designed

## Why

ROADMAP C02 locks message-passing channels on both targets (concurrency location: one spawn model, then channels). C02.01–C02.04 already land scalar/string send/recv, structured-clone (or designed) for plain objects with shared-ref reject, bounded buffer backpressure, and worker ↔ parent e2e; this cut is the parent row that those ops form one honest channel surface. C02 is on the C v1 done bar.

## Done

ROADMAP C02 is implemented test-first on both targets. A Program can send and recv on channels (scalars and strings), clone plain objects without sharing heap refs, apply the designed bounded-buffer / full-channel backpressure, and complete worker ↔ parent channel e2e. Tests under `tests/conformance` fixtures `concurrency/channels` lock that combined surface. Mark C02 `done` only when those tests are green.

## Blocked by

None. C02.01–C02.04 already land the per-class fixtures this parent row unifies. C01 worker spawn is already green on the child rows C02.04 needs.

## Non-goals

- **C02.01**: Channel send/recv: scalars + strings (already `done`)
- **C02.02**: Structured-clone (or designed) for plain objects; reject shared refs (already `done`)
- **C02.03**: Bounded buffer: backpressure / full-channel behavior as designed (already `done`)
- **C02.04**: Worker ↔ parent channel e2e (already `done`)
- **C01**: Worker / OS thread spawn isolate (parent row)
- **C03**: `once` / thread-safe init; mutex
- **C06**: shared-memory atomics
- user-facing shared JS heap across isolates
