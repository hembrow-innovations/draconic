# F07 Bindgen-ish: generate externs from C header subset

## Why

ROADMAP F07 locks bindgen-ish generation of Draconic `extern "C"` decls from a C header subset (ADR-0002 shared IR, ADR-0003 dual worlds). F07.01–F07.04 already land parse, emit, CLI write, and simple struct/typedef names; this cut is the parent row that those ops form one honest `draconic bindgen` surface. F07 deepens FFI after the F v1 done bar.

## Done

ROADMAP F07 is implemented test-first on the compiler target. `draconic bindgen <header>` parses a C header subset (scalar/pointer functions, simple structs, typedef names), emits Draconic `extern "C"` decls, and writes an extern module. Tests under `tests/integration` and `crates/draconic-cli` lock that combined surface. Mark F07 `done` only when those tests are green.

## Blocked by

None.

## Non-goals

- **F07.01**: Parse C header subset: functions with scalar/pointer params (already `done`)
- **F07.02**: Emit Draconic `extern "C"` decls from parsed header (already `done`)
- **F07.03**: CLI: `draconic bindgen <header>` writes extern module (already `done`)
- **F07.04**: Header subset: simple structs + typedef names (already `done`)
- **F06**: Manual `extern` decls (parse + check + IR/ABI)
- **F08**: Unsafe/native-only FFI diagnostics
- **F09**: wasm32/wasi emit
- full C preprocessor / rust-bindgen completeness (subset only; no full C)
