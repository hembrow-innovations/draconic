# K03 Module cache: layout, git clone/fetch, checkout by OID

## Why

ROADMAP K03 locks the module cache surface on the compiler target (ADR-0009 git-backed packages). Layout is keyed by module path + commit OID, git clone/fetch fills a VCS store (HTTPS; fixture repos in tests), and checkout of a pinned OID lands a package tree with cache hits skipping the network. K03.01–K03.04 already land layout, clone/fetch, OID checkout, and tree SHA-256; this cut is the parent row that those ops form one honest module cache.

## Done

ROADMAP K03 is implemented test-first on the compiler target. A Program's package graph can store git-backed modules in cache: layout keyed by module path + commit OID, clone/fetch into the VCS store, checkout of a pinned OID into the mod store (cache hit skips network), and SHA-256 over the canonical package tree. Tests in `crates/draconic-pkg` lock that combined surface. Mark K03 `done` only when those tests are green.
