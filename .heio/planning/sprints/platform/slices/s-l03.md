# L03 Crypto: SHA-256 digest + secure random bytes

## Why

ROADMAP L03 locks the stdlib crypto surface on both targets (stdlib location: honest portable libs a simple service needs). L03.01–L03.02 already land SHA-256 digest over bytes with known test vectors and secure random bytes from the OS CSPRNG with a length parameter; this cut is the parent row that those ops form one crypto library.

## Done

ROADMAP L03 is implemented test-first on both targets. A Program can SHA-256 digest bytes against known vectors and draw secure random bytes of a requested length through the designed crypto surface. Tests under `tests/conformance` fixtures `stdlib/crypto` lock that combined surface. Mark L03 `done` only when those tests are green.

## Blocked by

None. The ticket names no dependency. L03.01 and L03.02 already land the per-class SHA-256 and CSPRNG fixtures this parent row unifies.

## Non-goals

- **L03.01**: SHA-256 digest over bytes; known test vectors (already `done`)
- **L03.02**: Secure random bytes (OS CSPRNG); length parameter (already `done`)
- **L01**: Encoding UTF-8 / Base64 / hex
- **L04**: Compression gzip/deflate
