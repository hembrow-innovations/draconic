# R02.02 Deny path: clear diagnostic when host op lacks grant

## Why

ROADMAP R02.02 makes the deny path honest: when a host op lacks a grant, the Program gets a clear diagnostic instead of a silent success or an opaque failure. H04/H06 already land the host surfaces; this cut is the deny diagnostic of the optional Deno-like model (parent R02).

## Done

ROADMAP R02.02 is implemented test-first on both targets. Fixtures under `tests/conformance/fixtures/security/permissions` lock that a host op without a grant fails with a clear diagnostic. Mark R02.02 `done` only when those tests are green.

## Blocked by

None.

## Non-goals

- **R02 parent remainder**: the umbrella grant/deny model row
- **R02.01**: permission grants: fs read/write, net listen/connect (as designed)
- **R02.03**: CLI/runtime flags to grant subset (opt-in permissions)
- **R02.04**: default policy documented (permissive vs locked-down as designed)
- **H04 / H06**: filesystem and TCP surfaces themselves
- **R01**: embed/eval resource limits
- **R04**: panic/abort vs catchable exception policy
