# R04 Panic/abort vs catchable exception policy; fixtures per class

## Why

ROADMAP R04 makes panic/abort vs catchable exception honest on native: fixtures per class lock that user `throw` / ECMA errors stay catchable, while Runtime abort-class faults kill the process and never become JS values. R04.01 and R04.02 already land the two classes (ADR-0011); this cut is the parent row that the combined policy surface is honest.

## Done

ROADMAP R04 is implemented test-first on the native target. Fixtures under `tests/conformance/fixtures/security/panic_policy` lock catchable vs abort per class. Runtime tests under `crates/draconic-runtime` lock that `draconic_rt_abort` and invariant failures abort the process. Mark R04 `done` only when those tests are green.

## Blocked by

None. R04.01 and R04.02 already land the per-class fixtures this parent row unifies.

## Non-goals

- **R04.01**: document + fixture for catchable exceptions (already `done`)
- **R04.02**: document + fixture for process abort/panic (already `done`)
- **R01**: embed/eval resource limits (exhaustion is fail-closed at the C ABI, not a JS exception)
- **R05**: fuzz/stress hooks
- **R06**: panic backtraces with source locations
- **N09**: GC stress
