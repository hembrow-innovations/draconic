# R02 Permission model (optional Deno-like): grant/deny fs and net; clear deny diagnostics

## Why

ROADMAP R02 makes host fs/net grant/deny honest: an optional Deno-like permission model with clear deny diagnostics. H04/H06 children already land the host ops; this cut is the parent row that those ops can be granted or denied as a designed policy.

## Done

ROADMAP R02 is implemented test-first on both targets. Fixtures under `tests/conformance/fixtures/security/permissions` lock grant/deny for fs and net, and a denied host op produces a clear diagnostic. Mark R02 `done` only when those tests are green.

## Blocked by

None.

## Non-goals

- **R02.01**: permission grants: fs read/write, net listen/connect (as designed)
- **R02.02**: deny path: clear diagnostic when host op lacks grant
- **R02.03**: CLI/runtime flags to grant subset (opt-in permissions)
- **R02.04**: default policy documented (permissive vs locked-down as designed)
- **R01**: embed/eval resource limits
- **R03**: supply-chain policy tests
- **R04**: panic/abort vs catchable exception policy
- **H04 / H06**: filesystem and TCP surfaces themselves
