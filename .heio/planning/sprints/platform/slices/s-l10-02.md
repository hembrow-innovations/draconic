# L10.02 AEAD encrypt/decrypt (after L03; algorithm as designed)

## Why

ROADMAP L10.02 locks AEAD encrypt/decrypt on both targets (stdlib location: honest portable libs a simple service needs). This row is later than the L v1 bar and sits after L03 SHA-256 digest; the cut is one atomic Loop so a Program can AEAD encrypt and decrypt bytes through the designed crypto surface (algorithm as designed).

## Done

ROADMAP L10.02 is implemented test-first on both targets. A Program can AEAD encrypt plaintext with a key and nonce and decrypt the matching ciphertext back to the original bytes through the designed stdlib crypto surface. Invalid key, nonce, or ciphertext errors rather than silently succeeding. Tests under `tests/conformance` fixtures `stdlib/crypto` lock that AEAD surface. Mark L10.02 `done` only when those tests are green.

## Blocked by

None. L03 already landed (ROADMAP `done`; [[s-l03]] is archive-only).

## Non-goals

- **L10**: parent Crypto later HMAC + AEAD remainder
- **L10.01**: HMAC-SHA256 (after L03)
- **L03**: SHA-256 digest + secure random bytes (parent unify)
- **L03.01 / L03.02**: already `done` SHA-256 vectors and CSPRNG
- Web Crypto or Node `crypto` identity surface
- changing the L v1 done bar to require L10
