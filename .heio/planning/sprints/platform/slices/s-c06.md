# C06 Optional later: shared-memory atomics (advanced; not v1 bar)

## Why

ROADMAP C06 locks the deferred native shared-memory atomics surface (concurrency location: message-passing is the safer dual-world default; shared-memory/atomics later, not the C v1 bar). Worker isolates already exist (C01) and do not share a JS heap; this cut is the opt-in integer buffer those isolates can share with atomic ops.

## Done

ROADMAP C06 is implemented test-first on native. A Program can allocate a shared integer memory buffer visible to a worker isolate, then atomic load, store, add, compare-exchange, wait, and notify on that buffer without sharing a JS heap. The js target hard-errors (native-only). Tests under `tests/conformance` fixtures `concurrency/atomics` lock that surface. Mark C06 `done` only when those tests are green.

## Blocked by

None. C01.01–C01.04 already land worker isolates this row can share a buffer across. The ticket names no dependency.

## Non-goals

- **C01**: Worker / OS thread spawn isolate (children already `done`)
- **C02**: Message-passing channels (the v1 cross-isolate default)
- **C03**: `once` / thread-safe init
- **C04**: Parallel `draconic test`
- **C05**: Structured cancellation / timeout helpers
- shared JS heap across isolates
- full ECMA-262 `SharedArrayBuffer` / `Atomics` Test262 allowlist (E19 / S02)
- Node `worker_threads` SharedArrayBuffer identity
