# Pull target mapping out of the Checker

Parent: [[issues-6-architecture-cleanup]]

## Description

LLVM type name mapping lives on Checker `NativeType`. Semantic native types belong in Frontend/Checker; LLVM spelling belongs in the LLVM backend.

## Affected

Checker type surface; LLVM native-int/layout emit.

## Observed

`llvm_ty` (or equivalent) on Checker types used by backend emit.

## Impact

Small leak today; Frontend not target-neutral.

## Proposed Fix

Backend-owned map; remove LLVM naming from Checker public surface.

## Agent Brief

### Goal

Keep the **Checker** target-neutral: semantic **Native type** identity stays in the type system; LLVM type spellings live only in the **LLVM backend**.

### Contract

- Checker continues to model native types for dual-worlds checking.
- No public Checker API returns or embeds LLVM IR type name strings for codegen.
- LLVM backend owns the mapping from semantic native types to LLVM type text (or in-memory LLVM types if that exists later).
- Native codegen and JS native-only rejection behavior unchanged.

### Acceptance criteria

1. Checker public surface has no LLVM type-name helper used by backends.
2. LLVM native emit still produces correct types for i8–i64, u8–u64, f32/f64, bool, and existing layout/pointer paths covered by tests.
3. `cargo test --workspace` green.

### Out of scope

- Broader Checker splits ([[issues-12-split-mega-files-seams]]).
- Changing dual-worlds policy or native-only diagnostics text except if forced by API moves.
- JS backend changes beyond compile fixes.
