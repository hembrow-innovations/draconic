# Deepen Frontend into one compile module

Parent: [[issues-6-architecture-cleanup]]

## Description

CONTEXT.md names **Frontend** (parse, bind, typecheck). The repo has no Frontend module — every call site re-assembles parse|link → check → lower, including a fragile substring gate for import/export.

## Affected

CLI build, conformance compile path, Embed eval pipeline, and in-crate test helpers that currently wire stages by hand. Stage crates (parser, check, ir) remain implementation.

## Observed

Identical recipes duplicated across product and test entry points. Module programs gated by `contains("import ")` / `export `, not a parse-driven Script vs Module decision.

## Impact

Pipeline policy drifts per caller; agents re-learn the recipe every Loop. Prerequisite for clean Linker extraction ([[issues-11-linker-own-module]]).

## Proposed Fix

One deep Frontend module with a small compile interface; callers stop assembling stages.

## Agent Brief

### Goal

Introduce a single **Frontend** module that owns Program → IR compilation so CLI, conformance, Embed, and test helpers share one seam.

### Contract

- Public interface is small: compile from source text and/or filesystem entry path into `ir::Module` (optional intermediate `CheckedProgram` is fine if useful; must not force callers to wire stages).
- Script vs Module (link) decision lives **inside** Frontend. Delete the duplicated string `contains("import ")` / `contains("export ")` heuristic from call sites.
- Stage crates stay deep implementation details; do not expand their public surfaces just to paper over missing Frontend.
- Domain terms: Frontend, Program, IR, Checker — per CONTEXT.md.
- Observable compile/emit/test behavior unchanged except removal of the fragile heuristic (Module programs must still link correctly when they are modules).

### Acceptance criteria

1. A Frontend module exists with a documented small public compile interface used by CLI build, conformance fixture compile, and Embed’s compile path.
2. No remaining product call site uses the import/export substring heuristic.
3. In-crate helpers that previously inlined parse→check→lower use Frontend (or a thin wrapper over it) instead of re-assembling stages.
4. `cargo test --workspace` green.
5. CONTEXT.md Frontend definition still accurate (update only if the module name/role needs sharpening).

### Out of scope

- Extracting Linker into its own crate ([[issues-11-linker-own-module]]).
- LLVM multi-path / Runtime ABI work ([[issues-9-runtime-abi-seam]], [[issues-10-collapse-llvm-multipath]]).
- Changing IR shape, Checker rules, or language semantics.
- Mega-file splits unrelated to the new module boundary ([[issues-12-split-mega-files-seams]]).

### Suggested pickup order

Do this before [[issues-11-linker-own-module]].
