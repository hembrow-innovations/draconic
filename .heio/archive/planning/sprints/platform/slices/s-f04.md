# F04 Link external static lib (`.a`); call one symbol

## Why

ROADMAP F04 locks native static linking on the Dual-world FFI boundary (ADR-0002 shared IR, ADR-0003 dual worlds). A Program can link one external `.a` and call one C symbol without leaving Draconic. F04.01–F04.02 already land resolve-one-symbol and call-end-to-end; this cut is the parent row that those ops form one honest link-static / call-one-symbol surface. F04 is on the F v1 done bar.

## Done

ROADMAP F04 is implemented test-first on native. Native build links an external static archive (`.a`), resolves one C symbol, and calling that symbol observes the C return value end-to-end. Tests under `tests/conformance` fixtures `ffi/link_static` and `tests/integration` lock that combined surface. Mark F04 `done` only when those tests are green.

## Blocked by

None.

## Non-goals

- **F04.01**: Build links `.a`; resolve one C symbol (already `done`)
- **F04.02**: Call linked static symbol end-to-end (already `done`)
- **F05**: Link/load dynamic lib (`.so`/`.dylib`/`.dll`)
- **F02**: C callbacks (Draconic fn as `extern "C"` pointer)
- **F03**: C-compatible struct layout
- **F07**: Bindgen from C headers
- **F08**: Unsafe/native-only FFI diagnostics (js hard-error)
- js-target FFI (native-only until an explicit bridge row)
