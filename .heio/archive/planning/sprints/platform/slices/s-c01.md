# C01 Worker / OS thread: spawn isolate running module/fn; join/terminate; no shared JS heap by default

## Why

ROADMAP C01 locks worker / OS-thread isolates on both targets (ADR-0003 dual worlds; message-passing default, no shared JS heap). C01.01–C01.04 already land spawn from module or fn, join with result/error, terminate without sharing heap, and native OS-thread backing; this cut is the parent row that those ops form one honest worker surface. C01 is on the C v1 done bar.

## Done

ROADMAP C01 is implemented test-first on both targets. A Program can spawn an isolate running a module path or fn entry, join for exit result/error, and terminate the worker. Isolates do not share a JS heap by default. Native workers are OS-thread backed. Tests under `tests/conformance` fixtures `concurrency/workers` lock that combined surface. Mark C01 `done` only when those tests are green.

## Blocked by

None. C01.01–C01.04 already land the per-class fixtures this parent row unifies.

## Non-goals

- **C01.01**: Spawn worker isolate from module path or fn entry (already `done`)
- **C01.02**: Join worker: wait for exit; capture result/error (already `done`)
- **C01.03**: Terminate worker; no shared JS heap across isolates (already `done`)
- **C01.04**: OS thread backing for native workers (already `done`)
- **C02**: Message-passing channels
- **C03**: `once` / thread-safe init
- **C04**: Parallel `draconic test`
- **C05**: Structured cancellation / timeout helpers
- **C06**: Shared-memory atomics (later; not v1 bar)
- Node/Web Worker API identity or a shared JS heap
