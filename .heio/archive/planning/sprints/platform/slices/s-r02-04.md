# R02.04 Default policy documented (permissive vs locked-down as designed)

## Why

ROADMAP R02.04 makes the default permission policy honest and documented: whether the designed default is permissive or locked-down, a Program without explicit grants behaves as that default. H04/H06 already land the host surfaces; this cut is the default-policy contract of the optional Deno-like model (parent R02).

## Done

ROADMAP R02.04 is implemented test-first on both targets. Fixtures under `tests/conformance/fixtures/security/permissions` lock the documented default (permissive vs locked-down as designed) when no explicit grant subset is given. Mark R02.04 `done` only when those tests are green.

None.

- **R02 parent remainder**: the umbrella grant/deny model row
- **R02.01**: permission grants: fs read/write, net listen/connect (as designed)
- **R02.02**: deny path: clear diagnostic when host op lacks grant
- **R02.03**: CLI/runtime flags to grant subset (opt-in permissions)
- **H04 / H06**: filesystem and TCP surfaces themselves
- **R01**: embed/eval resource limits
- **R04**: panic/abort vs catchable exception policy
