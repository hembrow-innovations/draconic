# K11 Post-v1 packaging (not v1 bar)

## Why

ROADMAP K11 locks post-v1 packaging as later, not the v1 bar (ADR-0009 git-backed packages; K v1 done bar is K01–K08 + K09.02). Private git auth, `replace`, monorepo subdir module paths, proxy/mirror, and yank stay named children — this cut is the parent row that those ops are honestly later, not silent v1.

## Done

ROADMAP K11 is implemented test-first on the compiler target. The v1 packaging surface does not silently ship private git auth, `replace` fork/local override, multi-module monorepo subdir paths, module proxy/mirror, or yank/retract as v1 features; those remain later children. Tests in `crates/draconic-pkg` lock that later-not-v1 classification. Mark K11 `done` only when those tests are green.

None.

## Non-goals

- **K11.01**: Private git auth (HTTPS token / SSH)
- **K11.02**: `replace` directive: fork/local override
- **K11.03**: Multi-module monorepo (subdir module paths)
- **K11.04**: Module proxy/mirror (git still canonical)
- **K11.05**: Yank/retract when advisory source configured
- **K01–K10**: Manifest, lock, cache, resolve, CLI, build integration, integrity, E2E, in-repo demo (v1 bar and demo)
- npm-compatible registry or crates.io clone (rejected as v1 primary in ADR-0009)
