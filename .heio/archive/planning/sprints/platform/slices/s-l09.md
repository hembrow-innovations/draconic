# L09 MIME multipart later (HTTP-shaped programs; after H10)

## Why

ROADMAP L09 locks MIME multipart parse and serialize on both targets for HTTP-shaped programs (stdlib location: honest portable libs a simple service needs). This row is later than the L v1 bar (L01 + L03 + L05.01–02 + L06 + L08) and sits after H10 HTTP/1.1 helpers so a Program can build or read multipart bodies without leaving Draconic.

## Done

ROADMAP L09 is implemented test-first on both targets. A Program can parse a MIME multipart body (boundary plus parts with headers and bodies) and serialize parts back into multipart text through the designed stdlib MIME surface, including a common-case round-trip. Invalid or truncated multipart input errors rather than silently dropping parts. Tests under `tests/conformance` fixtures `stdlib/mime` lock that surface. Mark L09 `done` only when those tests are green.

## Blocked by

None. The ticket names H10 as sequencing; H10.01–H10.07 already land HTTP/1.1 helpers this later stdlib row can sit beside.

## Non-goals

- **H10**: HTTP/1.1 thin helpers (plaintext) on sockets
- **L08**: URL / query parse + serialize
- **L04**: gzip/deflate compression
- **L10**: HMAC / AEAD later
- full email MIME (message/rfc822), a MIME type registry, or Node `formidable` / `busboy` identity
- changing the L v1 done bar to require L09
